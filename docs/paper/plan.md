# 论文计划 / Paper plan

工作草稿。所有数字都必须来自可复现的实验运行（`~/.ctxport/distilled/run-*.json` 或 `benchmarks/`），不写未测量的结论。

## 暂定题目 / Working titles

- **Portable Memory: Lossless, Coverage-Guaranteed Migration of Personal Context Across LLM Assistants**
- 可携带的记忆：跨大模型助手的无损、可验证覆盖的个人上下文迁移

## 要回答的问题 / Research questions

- **RQ1 获取**：不依赖平台配合，能否从主流助手（ChatGPT、Claude、Codex、Gemini 等）无损取回用户的全部历史？各平台把数据存在哪里、以什么形式？
- **RQ2 提炼**：在给定长度预算下，哪种方法能保留最多的用户事实、编造最少？分层提炼 vs. 让旧助手“总结你对我的了解” vs. 一次性平铺总结 vs. 规则抽取。
- **RQ3 效用**：把迁移后的记忆交给一个全新的助手，它对用户相关问题的回答准确率提升多少？完整档案 vs. 精简版 vs. 检索（MCP）。
- **RQ4 成本与隐私**：每种方法的 token、时间成本；全本地流程能做到什么程度。

## 贡献 / Contributions (draft)

1. 一个统一、无损的对话数据模型和开源工具（ctxport），覆盖 9 个平台；对每个平台的真实存储格式做了测量与记录（例：某版 Codex 中 93% 的线程只存在 SQLite，rollout 文件已被清理）。
2. **覆盖可验证的分层记忆提炼（CHMD）**：L1 情节卡（带证据消息编号）→ L2 规范事实（每个 L1 事实恰好被一个 L2 事实覆盖，代码校验）→ L3 主题档案（每个 L2 事实至少出现一次，代码校验）→ L4 按目标预算渲染。模型漏掉的内容由程序补回，因此完整档案的覆盖率按构造为 100%；准确性（不编造）单独评估。
3. 一个评测协议：覆盖率–长度曲线、事实准确率、下游探针问答准确率、成本。
4. 模型无关：任何 OpenAI 兼容接口或“手动模式”（把提示词贴进任意聊天 AI），方便复现与比较不同模型。

## 方法细节（与代码对应）/ Method ↔ code

| 层 | 代码 | 关键保证 |
|---|---|---|
| L0 输入 | `distill.conversation_input` | 只发用户消息 + 截断的助手回答；代码/日志剔除；密钥遮蔽 |
| L1 情节卡 | `distill.build_cards` | 每条事实带证据编号；按内容哈希缓存，增量处理 |
| L2 规范事实 | `distill.premerge` + `merge_facts` | 覆盖不变量 `⋃covers = L1 ids`（`assert`）；模型漏掉的原样补回（计数 `l2_restored`） |
| L3 档案 | `distill.write_document` | 每个 L2 id 至少出现一次；遗漏补写（计数 `l3_appended`）；删除编造的 id |
| L4 渲染 | `distill.render_budget` | 按重要度（出现次数、是否用户确认、新近度）选取；报告 coverage@budget |

## 实验 / Experiments

### E1 获取保真度（RQ1）
- 对每个平台：源数据 → 库 → 导出，逐条精确比对（已有 3 个样本的脚本，扩展到全部对话或分层抽样）。
- 报告：对话数、消息数、分支数、注入内容识别率、失败/警告率。

### E2 提炼质量（RQ2）
- 基线：B1 让旧助手自述（真实的“总结一下你对我的了解”提示）；B2 规则抽取；B3 单次平铺总结（同一模型、同一预算）；本方法 CHMD；消融：去掉 L2 合并 / 去掉 L3 / 去掉覆盖补回。
- 金标准：从用户消息中人工标注原子事实（抽样 N 个对话，两人标注，算一致性）。
- 指标：
  - 覆盖率（召回）= 被输出蕴含的金标准事实比例（人工 + LLM 评委，报告二者一致性）
  - 精确率 = 输出中有原文依据的陈述比例（编造率 = 1 − 精确率）
  - 覆盖率–长度曲线（500 / 1500 / 4000 / 12000 / 不限字）
- 多个模型（不同服务商、不同规模）各跑一遍，看方法是否稳健。

### E3 下游效用（RQ3）
- 从金标准事实生成探针问题（“我在用什么编辑器？”“我的项目用什么框架？”），留出不参与提炼的部分做干扰检查。
- 条件：无记忆 / B1 / 精简版 / 完整档案 / 完整档案 + MCP 检索。
- 指标：探针准确率；对无关问题不过度使用记忆（误用率）。

### E4 成本（RQ4）
- 每种方法的调用次数、输入/输出 token、耗时（run 日志已记录）；增量更新的边际成本。

## 待验证的想法（2026-11-25，项目落地之后再做）/ Ideas to test later

来自讨论，均为假设，必须用实验证实或推翻：

- **精度–成本曲面**：每个方法、每个参数得到一个点（离线耗时与 token、在线 token、压缩后大小、精度）。主结果报 Pareto 前沿，不压成单一分数。
- **临界点**：用边际收益 ∂Acc/∂Size 定义曲线的拐点（knee）；检验是否存在“上下文太长反而变差”的局部峰值。
- **离线 vs 在线成本**：事先蒸馏成档案（离线一次）与每次检索（在线每问）之间的盈亏平衡提问次数 N*，先推公式再用实验验证。
- **加权分数**：权重来自真实成本（token 价格、延迟），并做权重敏感性分析；不手工拍定权重。
- **题库**：每类至少上百题才有统计意义（25 题置信区间约 ±20%）。题型：单一事实、长尾事实（只出现一次）、事实更新、多跳汇总、偏好、应拒答。合成人物植入事实后自动出题；另跑 LongMemEval、LoCoMo 等公开基准。
- **候选新方法**：常驻档案与检索的分层分配——按“被问到的概率 ÷ token 成本”决定事实放在哪一层（背包问题），与纯档案、纯 RAG 在同一总预算下比较。

## 用订阅跑实验的隔离协议（2026-11-25 实测，Claude Code 2.1.311）

56 次调用（Haiku×3、Sonnet×3、Opus×1，8 种条件，git 仓库外的临时目录）的结论：

- 默认 `claude -p` 会读入全局 CLAUDE.md：姓名、学校、专业、课程、项目全部泄漏（7/7）；英文提问也用中文回答。
- `--tools "" --setting-sources "" --strict-mcp-config` 挡住了 CLAUDE.md，但**订阅账号邮箱**仍被客户端注入上下文；Opus 还提到了本机用户名。
- 再加 `--system-prompt "You are a helpful assistant."`：仍有 6/7 次直接问到时报出账号邮箱，连“虚构用户 Alice”那组也报出真实邮箱（会污染合成人物）。
- 系统提示改为“忽略客户端提供的账号、邮箱、环境和路径信息，用户信息只以用户消息为准”：0/7 泄漏，虚构记忆照常被使用（7/7）。
- 邮箱仍在上下文里，只是被压住；正式实验应使用 API key + `--bare`（不读 OAuth 和 CLAUDE.md），订阅只用于试验。每批实验前用 `.leaktest/run_full.py` 复测。

## 合成人物基准 memsynth（2026-11-26 第一版）

代码：`benchmarks/memsynth/generate.py`（生成）、`score.py`（规则评分）、`vocab.py`（取值池和句式），不变量测试在 `tests/test_memsynth.py`。

**生成什么**：每个虚构人物有一份资料，事实写进用户消息里，分散在聊天应用（ChatGPT、Claude.ai、Gemini）和编程 Agent（Claude Code、Codex）的对话中，其余是不含个人信息的填充对话；中英文比例因人而异。
- 事实类型：固定事实、会变化的事实（搬家、换工作、换编辑器，最多变两次，更新语句写明“从 A 搬到 B”）、集合（用过的编程语言、去过的国家）、偏好（回答风格、回复语言）、需要链接两条信息的事实（姐姐的名字 + “她刚当上牙医”；项目 + 项目用的语言）。
- 提及次数：35% 只出现一次（长尾），45% 出现 2–4 次，20% 出现 5–9 次。
- 干扰项：同一取值池里的别的值，用在别人身上、假设、愿望和否定句里（“我朋友住在柏林”“如果我搬去里斯本”“我从没去过冰岛”）。每个人物有 3 个槽位从未提到，其中 2 个只出现在干扰句里，用来考“应拒答”。
- 取值池避开作者本人的学校、城市、课程和项目，所以模型自己上下文里的泄漏可以和合成历史区分开（测试会检查）。

**输出**：`conversations.jsonl`（ctxport 对话格式，`--db` 时直接写成一个 ctxport 库，`CTXPORT_HOME=<out>/<id>/home ctxport distill` 就能跑）、`facts.json`（每条事实的有效期和陈述它的消息编号）、`questions.jsonl`（标准答案、可接受的别名、陷阱值、证据消息、dev/test 划分）、`manifest.json`（每类题数和 95% 置信区间半宽）。

**题型**：single_fact、long_tail、update_current、update_previous、preference、aggregate_list、aggregate_count、multi_hop、abstain。评分是规则匹配：答出别名且不含陷阱值才算对；集合题要求全部答出、且不多说同一池里的别的值；拒答题要明确说不知道。标准答案得 1.0，“全部答不知道”只在拒答题得分（测试覆盖）。

**规模**（每人物 200 个对话、540 天，种子 2026）：每个人物约 2800 条消息、80 万字符，约 70 条事实陈述和 15 条干扰句。各题型题数随人物数线性增长：

| 人物数 | single | long_tail | upd_cur | upd_prev | pref | agg_list | agg_count | multi_hop | abstain |
|---|---|---|---|---|---|---|---|---|---|
| 8 | 51 | 28 | 30 | 34 | 16 | 16 | 16 | 16 | 27 |
| 40 | 231 | 167 | 145 | 161 | 80 | 80 | 80 | 80 | 137 |
| 80 | 491 | 304 | 288 | 322 | 160 | 160 | 160 | 160 | 277 |

约 70% 是 test。偏好、集合和多跳每个人物只有 2 题，要每类 100 道以上的测试题需要约 80 个人物；80 × 80 万字符的提炼成本太高，所以人物的对话数应作为实验变量调小（事实密度不变时，填充对话只增加长度）。

**已知局限（论文里要写）**：
- 句式来自模板，表面形式单一，字符串匹配类方法会占便宜。下一步：用 LLM 改写每条事实陈述，再程序检查取值仍在句中、没有引入新事实。
- 助手回复是通用填充，不会复述或编造用户事实；真实对话里助手的复述是一个混淆来源。
- 规则评分对自由回答偏严，需要用 LLM 评委复评一部分并报告与规则评分的一致率。
- 合成人物不能代替真实分布：真实数据只做汇总统计（例如作者本人的 ChatGPT 官方导出：2808 个对话、16314 条用户消息、约 268 万字符用户文本，2023-02 至 2026-11），不公开内容。

## 第二轮实验（2026-11-27 起，针对审稿式意见的五个不足）

代码：`benchmarks/migration/`（`llm.py` 三家模型的隔离调用与缓存，`pipeline.py` 各方法上下文与读者，`run_synth.py` 合成实验，`deletion.py` 删除/可审计性，`realdata.py` 作者本人数据，`analyze.py` 统计），公式修正见 `docs/paper/revision-math.md`。结果与缓存都写在 `~/.ctxport/research/`，不进仓库。

- **规模**：S 30 人物 × 80 对话（875 题），L 16 人物 × 320 对话（460 题），共 1335 题、46 个聚类；L 规模符号翻转检验的最小 p 为 2/2^16。
- **跨模型**：抽取 Claude Haiku（主）+ 本地 Qwen3.5-9B（10 个 S 人物）；读者 Claude Haiku / Sonnet、GPT（Codex CLI）、本地 Qwen。隔离协议复测：Claude 两档 0/8 泄漏、8/8 使用给定记忆。
- **新方法与基线**：`chmd-write@B`（模型只读 L2 事实写预算档案，读入量与历史长度无关）、`rolling@B`（按时间片滚动更新的摘要，模拟助手记忆的实际维护方式）、真实数据上的 `chatgpt-native-memory` 与用户粘贴的旧助手自述 `b1-*`。
- **真实数据（N=1）**：题目从作者原始消息里的自我陈述起草（不经过 CHMD），按首次提及年份 2023–2026 分层，作者在本地标注页确认答案；LLM 评委评分，报告按年份的准确率。只报告汇总数字。
- **统计**：人物级 bootstrap、精确/蒙特卡洛符号翻转、Holm、TOST（±5pp）、按式 (2′) 的损失分解与嵌套违反计数。
